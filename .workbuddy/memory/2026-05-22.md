## 核素+化合物匹配彻底重写（上午）

**现象**：国标法/modal 法计算后总剂量 = 0，日志显示 `[警告] 找不到核素 U_238 数据，跳过`。

### 根因1：_normalize_nuclide 函数上一轮说写但实际没有写入代码
- 上一轮修复说新增了 `_normalize_nuclide()`，但代码中实际不存在
- 本轮实际添加了该函数，并在 `get_nuclide_df()` 入口调用，下划线→连字符归一化

### 根因2：化合物→气溶胶类型映射错误
- parquet 数据中每种化合物只有**一个固定的气溶胶类型**（由 ICRP 文档决定）：
  - UO2/U3O8 → `Intermediate Type M/S`
  - UO3/硝酸铀酰 → `Intermediate Type F/M`
  - UF6 → `Type F`
  - PuO2/MOX → `Unspecified`
  - HTO/HT/OBT → `Unspecified`
- 之前 CSV 写的 `Type F` 在 parquet 中根本不存在对应的 UO2/UO3 行
- UI 下拉的气溶胶类型对这些化合物已无意义，改为由 `resolve_compound()` 自动推断

### 修复内容（dose_app.py）：
1. `_normalize_nuclide()` 函数：实际写入代码（下划线→连字符+strip）
2. `_COMPOUND_SHORT_TO_FULL` 升级为二元组字典 `{短名: (全名, 气溶胶类型)}`
3. `resolve_compound()` 返回 `(full_name, aerosol_type)` 二元组
4. `_do_calc` 中先按全名过滤 compound 列，再用推断气溶胶类型过滤 aerosol_type 列

### 验证结果（8个化合物全部通过）：
- U_238/UO2 → Intermediate Type M/S: e=4.8e-06
- U_239/UO3 → Intermediate Type F/M: e=2.4e-10
- U_238/UF6 → Type F: e=2.2e-07
- Pu_239/PuO2 → Unspecified: e=2.5e-05
- Pu_239/Pu_nitrate → Unspecified: e=1.3e-05
- H_3/HTO → Unspecified: e=2e-11
- H_3/HT → Unspecified: e=2e-15
- H_3/OBT → Unspecified: e=3.5e-11
