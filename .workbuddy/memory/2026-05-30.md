## monitoring_dose_app.py v2.4 重大重构（16:30）

### 数据加载策略：全量CSV → 懒加载分文件

**背景**：用户提出当核素扩展到数十~数百个时，单一 all_zdata.csv 会造成内存爆、启动慢。

**方案**：启动时仅扫描 `*_zdata.csv` 文件名建立索引，选中核素时按需加载该核素 CSV（`_nuc_cache` 缓存复用）。兼容模式：若无分文件则自动拆分 all_zdata.csv。

**新增函数**：
- `scan_z_data()` → 建立 `_nuc_index: dict[str, Path]`，不读数据
- `get_nuclide_df(nuclide)` → 懒加载 + 缓存
- `available_elements()` / `nuclides_of_element(elem)` → 元素/核素层级化接口

### UI 改动

1. **核素选择拆分为元素+核素两级**，同行布局（`cb_element` → 窄；`—`分隔；`cb_nuclide`）
2. **时间精度升级**：`spin_T` 由 1位小数 → **6位小数**，下限从1天降到0.000001天；显示标签同步为 6 位精度
3. **所有时间相关格式字符串** `:.4f` → `:.6f`

### 验证
- lint 零错误
- 懒加载 + 缓存复用验证通过
- 时间精度测试：t=0.5d、t=1.234567d、t=90d、t=0.000001d 均正确插值
