## Bug 修复 v2.3（2026-05-30 15:05）

### 根本 Bug：_fill_cb 永久封锁信号导致 UI 完全失去响应

**根因**：`_fill_cb(cb, items, block=True)` 执行 `cb.blockSignals(True)` 后从不调用
`cb.blockSignals(False)`，导致 cb_nuclide / cb_route / cb_material / cb_sample
的信号**永久**被封锁。用户在 UI 上的任何操作（切换途径、切换物质）均无法触发槽函数，
`cb_material` 始终显示 Inhalation 的 FMS 材料 → Ingestion/Injection 查询 material
字符串不匹配 → z(t) 返回 None。

**修复（6 处）**：
1. `_fill_cb` 重写：始终 `blockSignals(True)` 填充 + 始终 `blockSignals(False)` 解封，
   `block` 参数退化为语义标记，不再影响信号状态
2. `_on_nuclide_changed`：`_fill_cb(cb_route, ...)` 后，用 `cb_route.blockSignals(True/False)`
   包裹 `setCurrentText('Inhalation')`，防止触发 `_on_route_changed` 两次
3. `_on_route_changed`：同理包裹 `cb_material.setCurrentIndex(0)` 和
   `cb_sample.setCurrentIndex(0)`
4. `init_data`：包裹 `cb_nuclide.setCurrentIndex(0)`
5. 退化分支 `'无数据'` 调用移除 `block=True`
6. 代码中无残留 `block=True` 调用（re 检查确认）

**验证（5/5）**：
- Inhalation TypeF AMAD=5: z=4.300e-07 OK
- Inhalation TypeM AMAD=2.5 log-log: z=3.195e-06 OK
- Ingestion Soluble fA=0.02: z=4.100e-08 OK
- Ingestion Insoluble fA=0.002: z=4.200e-09 OK
- Injection fA=0.02: z=4.500e-06 OK

## Bug 修复（2026-05-29 14:39）

### 问题：RecursionError in _refresh_filter（pandas Series.name 递归溢出）

**根因**：`_fill_cb` 默认 `block=False`，在 `_refresh_filter` 内部调用时没有阻断 QComboBox 信号。
`cb.addItems / setCurrentIndex` 触发 `currentTextChanged` → 再调 `_refresh_filter` → 无限递归，
pandas 在比较操作中触碰调用栈上限，抛出 `RecursionError: maximum recursion depth exceeded`。

**修复**：将 `_refresh_filter` 内所有 `_fill_cb(cb, vals)` 改为 `_fill_cb(cb, vals, block=True)`，
并将 `_refresh_e_types` 中的 `_fill_cb` 同步加 `block=True`，彻底切断信号递归链路。
